PDFAI

How PDFAI uses the Google Cloud permission

PDFAI is a PDF reader. Users can ask Google Gemini about the text they select, using their own free Gemini API key. Creating that key by hand in AI Studio is hard for many people, so the app offers “Continue with Google”: it asks once for the scope https://www.googleapis.com/auth/cloud-platform and, directly from the device, does the setup in the user's own Google account.

What the app does with it (once, during setup)

  1. Creates a Google Cloud project named “PDFAI” in the user's account (or reuses the one it created before) — Cloud Resource Manager projects.create / projects.search.
  2. Enables the Gemini API (Generative Language API) and the API Keys API in that project — Service Usage services.batchEnable.
  3. Creates an API key restricted to the Gemini API and reads it — API Keys keys.create / keys.getKeyString.
  4. Reads the project's IAM policy to show in Settings which Google account the AI is connected with — projects.getIamPolicy.

The result is visible in the user's Google Cloud console: the “PDFAI” project, the two enabled APIs and the “PDFAI” key. The key is stored encrypted on the device and is only sent to the Gemini API. The access token is not stored and is cleared after setup. Disconnect in the app's Settings deletes the key and revokes the grant.

Why no narrower permission is enough

Scopes accepted by each call (from Google's API discovery documents):

CallAccepted scopes
cloudresourcemanager.projects.createcloud-platform only
serviceusage.services.batchEnablecloud-platform, service.management
apikeys.keys.createcloud-platform, apikeys
cloudresourcemanager.projects.getIamPolicycloud-platform, cloud-platform.read-only

Creating the project accepts only cloud-platform, and a user who has never used Google Cloud has no project to put the key in. A read-only scope cannot create anything. So cloud-platform is the minimum scope that makes the feature work, and the app requests nothing else.

Google user data

The app only touches the “PDFAI” project and key it creates and the email address of that project's owner (shown in Settings). It does not share, transfer or disclose Google user data to anyone: the app has no server and the developer never receives it. Details in the privacy policy.
